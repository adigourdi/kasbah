A failure prints what failed and why, then what to do next, a `kasbah help`
topic where one fits, and last the log it saved:
  error: cannot reach you@vps over ssh (see ssh's own error above)
         Make `ssh you@vps true` work from this shell first: …
         help: kasbah help troubleshooting
         log: ~/.local/state/kasbah/logs/20261115T120102.345Z-deploy.log

The failures a new project meets most, and where to start:
  No kasbah.yml in current directory   run from the project root, or
                                       kasbah init-project to write one
  invalid project name '…'             init-project --name=<name>: the
                                       directory's own name does not fit
  cannot reach … over ssh              make `ssh USER@HOST true` work first
  could not tell which user ssh logs   pass USER@HOST: a bare host takes the
  in to … as                           user `ssh -G HOST` prints
  ssh logs in to … as root, and        type root@HOST to act as root, or
  kasbah takes root only when typed    USER@HOST for the operator you are
  passwordless sudo — `sudo -n true`   run the printed commands as root once,
  failed                               or server init from a terminal
  … has no server marker at …          not prepared yet (kasbah server init),
                                       or prepared at another --apps-path
  the server runs kasbah X, newer …    kasbah self-update to that version
  the working tree differs from HEAD   commit and tag, or ship it with --dirty
  HEAD carries no version tag          tag it (git tag v1.0.0), or --bump=patch
  no terminal here to render it on     kasbah env from a terminal, or
                                       --env-seed=FILE / --on-drift=
  … did not become healthy within Ns   kasbah logs USER@HOST says why
  a compose project named … already    docker compose -p NAME down there, or
  exists / … publishes …               rename; free the port the line names
  traefik-dynamic.yml cannot be        kasbah env set KEY USER@HOST, as the
  rendered: ${…} is not set in …       line says, then deploy again
  could not load the images onto …     a full disk is the usual cause
  could not list the releases of …     why is on the error: line, what to do
                                       on the next: reach GitHub (HTTPS_PROXY)
                                       or wait out a rate limit
  … checksums.txt does not verify      a download cut short is a retry; a
  / sha256 …, checksums.txt says …     signature or sha256 that fails again
                                       is worth a report: install none of it
  cannot write …/kasbah                chown the directory (or the one above
                                       it) back, or export KASBAH_BIN_DIR as
                                       a directory you own, on PATH

Each entry, with the exact text to search for, is in troubleshooting.md.
