# Phase 1 — Rig ✅ done

> A disposable fake VPS exists: kasbah commands can SSH into a container
> that runs its own Docker daemon, and an integration-test runner drives it
> headless.

**Prerequisite:** Phase 0 committed.
**Spec:** `docs/server-setup.md` (prerequisites table — the rig must satisfy it), `docs/cli.md` (exit codes the tests will assert)
**Retires:** "can a container fake a VPS well enough to be the standing exit bar" — the premise of the whole test strategy.

## Decisions settled at execution time

- **Ports 5022/5080/5043, not 2222/8080/8443.** 8080 was already bound on
  the dev machine; a rig that can't `up` out of the box is worse than a
  plan edit. All three are env-overridable, and the integration suite
  curls from *inside* the rig so it never depends on a free host port.
- **The keypair is generated by `rig.sh up`, not committed.** An SSH
  private key in git history is permanent and trips push protection.
  A clean checkout still works with zero manual steps.
- **The SSH user is `stevedore`, not root; root login is disabled.** The
  prerequisites table's "can run docker without sudo" row is vacuous as
  root, and the repo owner doesn't log in as root. `stevedore` is in the
  `docker` group and has passwordless sudo.
- **The image does not pre-create `/apps`.** Deliberate: it leaves Phase 2
  facing the real question of who creates it under a non-root user
  (see 02-spine.md), instead of hiding the answer in the rig.

## Exit criteria

Walked at phase close against the real rig, from a cold keyless start, and
re-walked after the group review's fixes.

- [x] `tests/rig/rig.sh up` → `ssh` into the rig succeeds with key auth — **2.2 s** from no keypair and no container, lands as `stevedore`; root login refused
- [x] `docker run hello-world` works **inside** the rig over that SSH session — pulled, not cached
- [x] `tests/rig/rig.sh reset` returns a pristine rig in under a minute — **4.2 s**, `images=0 containers=0` inside afterwards
- [x] `KASBAH_RIG_TESTS=1 ./test.sh` runs the integration suite; without the var, the unit suite is unchanged and fast — 5 PASS vs 4 PASS; the integration delta is ~3 s against a ~1m40–2m00 suite whose own host-load swing is ±20 s. With the rig down: `SKIP smoke_test.sh — preconditions not met`, exit **2** (environment, not test failure)
- [x] Rig limitations documented — `tests/rig/README.md`. ACME cannot issue (no public DNS, nothing reaches :80 from outside); until Phase 6, TLS is asserted as "Traefik serves HTTPS at all" (`curl -k`), never as "a valid certificate was issued"

**Not proven here, by construction:** that the rig resembles a real VPS
beyond the prerequisites table. No systemd, no reboot, no kernel of its
own, no disk or memory pressure worth trusting, no firewall, and resource
limits computed inside it reflect the workstation. Phase 6 is the honest
test; that is why it exists.

## Tasks

### 1.1 — DinD image + compose (M) ✅
`tests/rig/` — Dockerfile (Debian slim + docker-ce + openssh-server), a
`compose.yml` running it `privileged: true`, entrypoint that starts
`dockerd`, **waits for `/var/run/docker.sock`**, then starts `sshd`.
Dedicated keypair, generated on first `up` and gitignored. Ports:
5022→22, 5080→80, 5043→443, each overridable via
`KASBAH_RIG_{SSH,HTTP,HTTPS}_PORT`. Named volume for `/var/lib/docker`.

**Deliverables**
- [x] `tests/rig/Dockerfile`, `tests/rig/compose.yml`, entrypoint script
- [x] SSH as `stevedore@localhost:5022` with the rig key succeeds — `groups=1000(stevedore),999(docker)`, root SSH refused `Permission denied (publickey)`
- [x] `docker info` inside the rig shows a working storage driver — `overlayfs`, server 29.7.2, **not** vfs; `docker run --rm hello-world` pulls and runs inside the rig

**Observed:** docker-ce 29.7.2, containerd.io 2.3.3, compose plugin v5.4.0,
buildx 0.36.1 on debian:bookworm-slim. Image 475 MB, 21 s cold build.
`up` → SSH-ready-with-working-docker in **1.6 s**. `docker stop` returns in
1.2 s (exit 143). MTU pinned to 1500 from `/sys/class/net/eth0/mtu`.

**Watch out for:** overlayfs-on-overlayfs — without the named volume,
nested dockerd falls back to vfs or fails outright. Also dockerd startup
race (gate sshd on the socket, or tests flake), and MTU mismatch in
nested networks (symptom: TLS handshakes hang; fix: set dockerd MTU to
the outer network's).

### 1.2 — Rig lifecycle script (S) ✅
`tests/rig/rig.sh up|down|reset|ssh` — reset = down -v && up && wait for
SSH. A rig-local ssh config (`StrictHostKeyChecking=no`,
`UserKnownHostsFile=/dev/null`, port, key) that every caller reuses, so
resets don't churn known_hosts.

**Deliverables**
- [x] `rig.sh` with the four verbs, each idempotent — `up`×2, `down`×2, `reset` from either state, `ssh` when down (255 + hint) all verified
- [x] `rig.sh ssh -- docker info` works from a clean checkout — cold keyless `up` generates the keypair and is ready in **2.0 s**, from any cwd

**Observed:** `reset` **2.6 s** from down, **3.5–4.5 s** from running (bar is
60 s), and genuinely pristine — nested images, containers and volumes all
gone. No-op `up` costs 0.7 s. Connection contract is a generated
`tests/rig/ssh_config` (gitignored); `rsync -e` and `scp -F` against it
both verified, so Phase 2 reuses it rather than restating flags.

**Watch out for:** waiting on "container is up" instead of "sshd answers"
— poll the SSH port with a timeout, not `sleep`. *Went further in
practice: even the compose healthcheck is too weak — see Findings.*

### 1.3 — Integration runner + smoke test (S) ✅
`tests/integration/` with the same assert-helper idiom as the unit tests.
`test.sh` runs it only when `KASBAH_RIG_TESTS=1`. First test: rig
reachable, docker functional, `rsync`/`gzip`/`openssl` present (the
`server-setup.md` prerequisites table, asserted).

**Deliverables**
- [x] `tests/integration/smoke_test.sh` green against a fresh rig — asserts all five prerequisite rows plus `docker run --rm hello-world` inside the rig
- [x] `./test.sh` timing unchanged when the var is unset — the unset path costs one string comparison; instrumented with `PATH` shims, **zero** external calls when off, exactly one SSH session when on

**Observed:** smoke suite **~4.0 s** standalone; back-to-back pairs put the
integration delta at 3–6 s against a ~1m40–2m00 unit suite, where host load
swings ±20 s and swamps it. Every assertion was watched going red on a
false premise; every probe key was watched going missing.

**Watch out for:** every kasbah command the suite will ever run must be
flag-driven (CLAUDE.md, "Interactive, never assume") — no test may ever
block on a prompt.

**Not assertable in this phase:** the plan wanted the smoke test to prove
`kasbah` fails loudly rather than hangs when a required flag is missing
with no TTY. No command with a prompt exists until Phase 2, so there is
nothing to assert against. The assertion lands in 2.6, where 02-spine.md
already expects it.

## Findings

### From 1.1

- **DinD works on this host, comfortably.** Nested dockerd answers 1.6 s
  after `up`, storage driver `overlayfs` (containerd snapshotter) with the
  named volume in place — no vfs fallback, no MTU surprise (outer docker0
  is 1500, so the plan's MTU warning didn't bite; dockerd is pinned to the
  measured value anyway so a VPN'd machine doesn't rediscover it).
  Versions baked: docker-ce 29.7.2, containerd.io 2.3.3, compose v5.4.0.
- **Bind-mounting a host file that may not exist is the acme.json trap
  from the other side.** The rig originally mounted `id_ed25519.pub`; on a
  checkout without a keypair Docker materialises the missing source as a
  **root-owned directory on the host** — at a gitignored path, so
  `git status` never shows it and the later `ssh-keygen` can't overwrite
  it without sudo. The guard didn't fire because **`[ -r ]` is true for a
  directory**. Fixed structurally: the key travels in the environment
  (`KASBAH_RIG_PUBKEY` → `RIG_AUTHORIZED_KEY`), so there is no host path
  to materialise. *Rule for later phases: never bind-mount a host file
  kasbah doesn't itself guarantee exists — and `-r`/`-e` don't
  distinguish file from directory; use `-f`/`-s`.*
- **`build:` + `image:` in compose means `up` never rebuilds.** An edited
  Dockerfile is silently ignored as long as the named image exists.
  Rebuild control therefore belongs to `rig.sh` (1.2), explicitly.
- **A stale `/var/run/docker.pid` survives `docker restart`.** `/run` is
  part of the container filesystem, so dockerd is handed its own previous
  pidfile and aborts with "process with PID n is still running". The
  entrypoint removes the pidfile and socket before launching. `rig.sh
  reset` would have tripped over this.
- **`openssh-server`'s postinst bakes host keys into the image.** Deleted
  at build; `ssh-keygen -A` runs per container instead. The image now
  ships no private key of any kind (verified by grep over the layers).
- **Healthchecks lie by default.** The first version proved *a TCP
  listener on :22* and *root can reach docker* — both true while the rig
  was unusable (empty `authorized_keys`), and root's `docker info` doesn't
  exercise the "SSH user can run docker without sudo" prerequisite row at
  all. It now checks `docker info` **as `stevedore`**, a non-empty
  `authorized_keys`, and the listener. It still cannot prove the installed
  key is the *right* key.
- **A dead dockerd used to leave the container `running`.** With `exec
  sshd` as PID 1, killing dockerd post-gate produced a rig that answered
  SSH and failed every docker command — the ideal flake generator for
  later phases. The entrypoint now `wait -n`s on both children and takes
  the rig down when either dies, with a TERM/INT trap so `docker stop`
  still returns in ~1.2 s.
- **Published ports defaulted to `0.0.0.0`.** A privileged container whose
  SSH user has passwordless sudo, reachable from the LAN, is
  root-equivalent on the workstation. Now `${KASBAH_RIG_BIND:-127.0.0.1}`.

### From 1.2

- **`name:` in a compose file is not a pin — it is the *weakest* source of
  the project name.** Precedence is `-p` > `COMPOSE_PROJECT_NAME` >
  `name:`. With that variable exported for another stack,
  `docker compose -f tests/rig/compose.yml ps -a` listed **nine unrelated
  live containers** on this workstation, and `down -v` removes by project
  label, not by services named in the file — so `rig.sh down` from the
  wrong shell would have taken them with it. Every compose invocation now
  passes `-p kasbah-rig`. **Carry to Phase 2:** kasbah runs
  `docker compose` on the VPS too, and inherits the same hazard from the
  remote environment. Pass `-p` there as well.
- **The compose healthcheck reports `healthy` on a rig nobody can log
  into.** Observed by planting a *mismatched* public key: `health=healthy`
  alongside `Connection closed by authenticating user stevedore [preauth]`.
  `rig.sh` therefore waits on a real `ssh … docker info` probe, which is
  also ~8 s faster than the healthcheck's first poll (one full `interval`
  after start). A healthcheck is a monitoring signal, not a readiness gate.
- **`cat > shared_file` is a truncation race.** `O_TRUNC` leaves a
  zero-byte window in which a concurrent reader sees no `Host rig` block
  and treats `rig` as a real hostname — a misleading DNS error. Measured
  directly: truncate-in-place 15 of 68 reads saw an empty file;
  render-to-temp + `mv -f` (atomic rename), 0 of 1046. Anything generated
  for other processes to read gets the rename treatment.
- **A bash `RETURN` trap stays installed after the function that set it
  returns.** `trap 'rm -f "$tmp"' RETURN` fired again on a later,
  unrelated function's return, against an out-of-scope `local tmp` — under
  `set -u` that aborts a *successful* command with `tmp: unbound
  variable`. Clean up inline; don't reach for RETURN traps here.
- **`ssh-keygen -y` does emit the key's comment field** (3 fields, not 2),
  so re-appending one doubles it. Only type+blob are compared when
  validating a stored `.pub`.
- **The rig's sshd is `maxstartups 10:30:100`.** More than ~10 concurrent
  SSH sessions get random early drops — `Connection closed`, exit 255.
  Relevant to 1.3 and to any later suite that fans out.
- **`ssh host cmd args` re-joins the arguments with spaces**, so quoting is
  the caller's job: `rig.sh ssh -- docker info --format '{{.Driver}}'`
  reaches the rig as two words and fails. Wrap the remote command in a
  single quoted string.
- **Accepted limit:** a checkout path containing spaces breaks the
  generated `IdentityFile` line and the `rsync -e "ssh -F …"` recipe. Not
  fixed — a partial fix that left the recipe broken would be worse than a
  known limit.

### From 1.3

- **A "missing" marker value makes non-emptiness assertions unfalsifiable.**
  A `field()` helper printed `<no X reported>` for an absent key so failures
  would name it — but that string is non-empty and `!= "0"`, so four
  assertions could never fail, and with `hello_greeting` absent the suite
  **exited 0, silently green**. Fix the class, not the call sites: parse the
  probe output once, validate the complete expected key set as a *protocol*
  before any assertion reads a value, and let lookups be plain lookups.
  A test that goes green because a fact went missing is the exact failure
  this phase exists to prevent.
- **`ConnectTimeout` bounds connection setup, not execution.**
  `ssh … 'sleep 20'` returns after 20 s with `ConnectTimeout 5` set. An
  established session that stalls — a wedged rig, a pull that connects and
  then hangs — is unbounded. The probe is wrapped in `timeout`, with exit
  124 given its own branch so a stall isn't misreported as transport
  failure. (`timeout(1)` is now a local dependency.)
- **A boolean env gate that only matches `=1` turns `=true` into a false
  green.** `KASBAH_RIG_TESTS=true` printed the same three PASS lines and
  the same exit 0 as a run where the integration suite really passed.
  Unset/empty/`0` are off, `1` is on, anything else exits before any suite
  runs, naming the accepted values.
- **`test.sh`'s exit codes are its own contract** — 0 pass, 1 tests failed,
  2 runner misconfigured. `docs/cli.md`'s table (2 = not a kasbah project,
  …) governs the `kasbah` CLI only; it is not a repo-wide numbering scheme.
- **Accepted limit:** the smoke test is not hermetic — it pulls
  `hello-world` from Docker Hub on every run and deletes it afterwards, on
  purpose. A cached image would reduce the assertion to "a local image
  starts", which is not what "docker functional" means. Registry failures
  were checked and are diagnosed exactly (refused: 0.3 s, unroutable:
  11.6 s, both naming the cause).

### From the phase-close group review

The three tasks were each reviewed in isolation. A fourth reviewer that had
seen none of the rounds judged them together, and found what per-task
review structurally cannot — defects that live in the *seams*:

- **A shared generated file rendered from per-caller environment is a
  poisoning hazard.** `rig.sh` re-rendered `ssh_config` from
  `$KASBAH_RIG_SSH_PORT` on *every* verb, while the publish side was fixed
  when the container was created. So one stray `KASBAH_RIG_SSH_PORT=15022
  rig.sh ssh` permanently repointed the contract, and the integration suite
  then failed with "is the rig up?" against a rig that was up and healthy.
  Now the endpoint is read back out of Docker; the environment is consulted
  only when no container exists. **`docker port` alone is not enough — it
  fails outright on a container that exists but is *stopped*.** Fall back to
  `HostConfig.PortBindings`, recorded at create time, which survives a stop.
- **An env knob the container never receives is a dead knob.**
  `entrypoint.sh` read `KASBAH_RIG_DOCKERD_TIMEOUT`, but `compose.yml`
  passed only `RIG_AUTHORIZED_KEY`, so it was permanently 90 s. It was also
  named with the host-side prefix while being read *inside* the container,
  where the convention is `RIG_*`. A container sees exactly what the compose
  file declares and nothing else.
- **Two comments taught the unsafe form of the very rule the phase had just
  fixed** — a `docker compose` recipe without `-p`, in a repo whose README
  says always to pass it. Rationale that lives in four places (code comment,
  Findings, commit message, README) is a drift engine; the fix keeps them in
  step, but the count is worth watching.
- **`rig.sh` had no tests**, against CLAUDE.md's "tests land with the code
  they test". Now `tests/rig_test.sh` covers the branches that cost two
  review rounds — verb-argument rejection, the mismatched-`.pub` guard, the
  not-a-plain-file guard, endpoint resolution including the stopped-container
  case, and that every compose call carries `-p`. It is hermetic: a copied
  script plus a stub `docker` on `PATH`, so it passes with the rig down and
  on a machine with no Docker, and it costs 0.25 s.
- **`test.sh` now separates "the tests failed" from "the environment is
  wrong."** A suite exiting 2 prints `SKIP <suite> — preconditions not met`
  and makes the runner exit 2. A downed rig is not a test failure, and in CI
  the exit code is often all you get.
