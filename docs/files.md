# Files kasbah writes

Every path kasbah writes, on the workstation and on a VPS, with the command
that writes it, what reads it, its format and the spec that owns that format,
its mode, its owner, and what rewrites or removes it. This is a
contract: a binary that writes a
path not listed here, or a listed path with a different mode or owner, has
changed a contract. Formats are not restated — each row links the spec that
owns it (`project-manifest.md` for the state file, `server-setup.md` for the
VPS layout, the pointer and the marker, `build-deploy.md` for `versions.log` and
the helper scripts, `backup.md`, `mail.md`, `traefik.md`).

`tests/integration/files_test.sh` reads the tables below as data, so their
shape is part of the contract:

- **Path** is one backticked pattern. `<apps>` is the apps path (default
  `/apps`), `<data>` the data path (default `<apps>/data`), `<tmp>` the
  workstation's `${TMPDIR:-/tmp}`, `<project-dir>` the project's checkout,
  `~` the invoking user's home, `<project>` the project's `name:`. Any other
  `<name>` is one path segment (`<pid>`, `<stamp>`, mktemp's `XXXXXX` as `*`),
  `*` matches within a segment, and `/**` — at the end or mid-pattern — stands
  for the entry itself or any depth below it (`a/**/*.tmp` covers `a/x.tmp` and
  `a/b/c/x.tmp`).
  `<path>` rows (whatever `sync:` names) document but never vouch for a file.
- **Mode** and **Owner** are checked when the cell is exactly one backticked
  value. `deploy` is the ssh user and its primary group; `deploy:kasbah` is
  the ssh user and the operators' group (`server-setup.md` → Operators).
  Anything in prose ("umask") is a value the code does not fix: every
  `kasbah remote …` step runs at umask `002`, so the rig shows `775`/`664`
  under the apps path — `2775` for a directory below a setgid one.
- **Code** is the writer's `file:line`; lifecycle references are inline.
- *Transient* rows are files a successful run removes; they are listed
  because a failed or killed run leaves them behind.

Every command that reaches a server creates `<tmp>/kasbah-ssh.*`, and every one
that records `last_server` (`history`, `pending`, `changelog`, `logs`, `exec`,
`check --server` among them) merges `state.json`; beyond those two rows, the
commands not named as writers below write nothing — `check` (but see `--fix`),
`server status`, `mail-setup-guide` and `server prune` only read or remove.

### The install (`install-dev.sh`, `self-update`)

`<lib>` is `KASBAH_LIB_DIR`, else `$XDG_DATA_HOME/kasbah`, else
`~/.local/share/kasbah`; `<bin>` is `KASBAH_BIN_DIR`, else `~/.local/bin`. Both
writers place a build through `internal/install`: `<bin>` is checked writable
first, then the build is placed, the symlink moved, and other dev builds removed last.

| Path | Writer | Readers | Format → spec | Mode | Owner | Lifecycle | Code |
|---|---|---|---|---|---|---|---|
| `<lib>/<version>/kasbah` | `kasbah __install [DIR]` from `install-dev.sh` (`dist/`, or a tag's `dist/` built in a temporary clone); `self-update` (streamed, size + sha256 checked against the signed `checksums.txt`) — each written beside as `.kasbah.new` and renamed, `<version>` being the build stamp | the symlink; a hand-off (`cli.md` → Hand-off) | static ELF (Mach-O on macOS) for this machine | `755` | the installing user | a re-install of the same stamp replaces it; a dev build is removed by the next dev install, a release never | `internal/install/install.go:159` |
| `<lib>/<version>/server/kasbah-linux-<arch>` | `__install` (amd64 and arm64 from the build's `server/`); `self-update` (on Linux this machine's arch, a copy of its own binary; on macOS both arches, downloaded or read from `--from`); `serverbin.Local` fetching the missing arch of an installed release the same verified way | `serverbin.Local` — what that version ships to a server | static linux ELF | `755` | the installing user | as above | `internal/install/install.go:185`, `internal/serverbin/serverbin.go:56` |
| `<bin>/kasbah` | `__install` and `self-update`: a symlink to the newest installed version that runs and survives the prune (a version argument to `self-update` or `install-dev.sh`: the version it resolved to), through `<bin>/.kasbah.new` and a rename | the shell | symlink | — | the installing user | repointed by every install; a regular file there is replaced, a directory refused | `internal/install/install.go:300` |

Each file is first written beside its name — `<lib>/<version>/.kasbah.new`,
`server/.kasbah-linux-<arch>.new`, a download as `..kasbah.new.part` — and renamed;
a Ctrl-C removes them, a hard kill can leave one, which the next install replaces.

A library is refused unless it is empty or holds a directory named as a version,
so a library from before 1.0.0 (`<lib>/server/kasbah-linux-*` at the top, or
`libexec/`, `VERSION`, `*.sh`) is refused rather than adopted: remove it by hand.

`get.sh` writes only a `mktemp -d` directory under `$TMPDIR` — the release
asset, `checksums.txt` (and `.minisig`), and, for the token rung, a `600` header
file removed as soon as that rung returns — removed on every exit; it then hands
off to the downloaded binary's `self-update`, which writes the rows above.

Developer tooling, not the CLI: `release.sh keygen` writes the minisign pair
`${KASBAH_RELEASE_KEY:-~/.config/kasbah/release.key}` (`600`, its directory
`700`) and `<repo>/release.pub` (committed, embedded in the binary);
`release.sh vX.Y.Z` writes the next `-dev` into `<repo>/VERSION`
(`release.sh:46`, `:133`).
